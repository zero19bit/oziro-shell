# Oziro V2 — Foundation 0.8 (experimental)
Native Arch / Hyprland and Niri shell, independent of the legacy Rust/React host. Not a production release.

## Test on a real Wayland session
Install the official Arch package quickshell (target API 0.3.2), plus UPower and PipeWire/WirePlumber where needed. Do not run as root. Existing bars may compete for space; temporarily stop them yourself.
```sh
bash native/doctor.sh
quickshell -p "$PWD/native"
```
Ctrl+C stops the foreground instance. No compositor configuration is rewritten. Click OZIRO to search graphical installed apps (terminal-only desktop entries excluded); Controls opens audio, themes, layouts and shell eco mode. Close popups before testing another monitor. Theme, layout and shell effects are saved in the Oziro state directory; no Ryoku settings are changed. Glass is translucent color, not real blur.

Optional isolated install: `bash native/install.sh`. It refuses an existing destination and does not install dependencies, change autostart, or replace your current shell.

## Verification
QML targets documented Quickshell 0.3.2 APIs, but still requires actual Arch/Hyprland and Niri runtime verification. See TEST-001.md and TEST-002.md for user-reported results; see TEST-003.md for 0.3 memory observations; no hardware power savings have been established. Report exact logs and test monitor hotplug, popup focus, no audio, AC/battery transitions, all palettes and all layouts. Run `bash native/benchmark.sh PID 60` to sample process PSS/RSS and cumulative CPU ticks. Compare same machine, display setup and workload, with old shell stopped. This measures one process, not total session or battery usage.

## Scope
Implemented in source: per-screen panel, real workspace activation, clock, default audio mute/volume, battery status, on-demand launcher, control center, five provisional palettes, three panel placements, battery-aware reduced shell effects, user-copy installer and measurement helper. No always-on AI, sync or animated wallpaper.
Not yet implemented: dock auto-hide, Hyprland running-window tracking, notification actions and disk history, Wi-Fi scanning and connection, Bluetooth pairing, tray, advanced power policy, graphical setup, plugin isolation, widgets, lock screen, update mechanism, CI runtime tests or OS image. See VISION.md.

## Foundation 0.2 changes
Niri backend uses a single event stream socket with reconnect on disconnect and a separate bounded action connection. The panel chooses Niri when NIRI_SOCKET is set; battery selection falls back to a present physical laptop battery. Both changes passed the user-reported Niri test (see TEST-002.md). No compositor files are modified.

## Foundation 0.3
Cold panel uses QtQuick-only controls and loads popup QML by URL when requested. Both popups share one loader per output, and icon caching is disabled in the launcher as an experiment. This may trade some reopen latency for lower retained memory; benchmark before claiming a gain. OZIRO_PANEL_ONLY=1 disables popup entry points for isolation. Preferences use atomic JSON writes in the shell's XDG state directory. Only one Oziro instance should write these settings. The new installer includes the previously omitted Niri backend. Run `bash native/measure.sh PID cold 60`, then open/close both popups and run `bash native/measure.sh PID warm 60`. Compare with matching 0.2 tests. CPU is an approximate tick-based average; GPU/whole-system power is not measured.

## Foundation 0.4
Enable Dock in Controls; off by default to keep the panel baseline comparable. Pin/unpin installed graphical applications with +/- in the launcher (up to 12). Dock is on the opposite edge from the panel; running windows on Niri use the existing event stream and click-to-focus IPC. Pinned launches work independently of Niri. Matching app IDs to desktop entries is heuristic, so unmatched windows appear separately. No thumbnails, drag reorder, auto-hide or Hyprland running-window tracking yet. Dock visual surface is unloaded when disabled; Niri compact window metadata remains in the shared adapter. Retest with dock on/off and check settings persistence. User-reported 0.4 functionality: 10/10 checks passed on Niri (TEST-004.md); no dock memory benchmark yet.

## Foundation 0.5
Control Center adds Wi-Fi radio and Bluetooth adapter toggles, backlight steps with a 5% floor, battery state and optional system power profiles. The bounded helper runs only when the popup opens, after an explicit action, or on Refresh. No periodic polling, no password handling, no sudo, no auto-install. Requires optional NetworkManager/nmcli, BlueZ/bluetoothctl, brightnessctl and powerprofilesctl respectively. Existing power managers are not reconfigured. Turning off Wi-Fi or Bluetooth can disconnect devices; test only when safe. System controls show unavailable when services are absent. External changes require Refresh. Wi-Fi network selection and Bluetooth pairing are not included. Test runtime and actual hardware permissions on Arch. The helper can be checked independently with `bash native/system-controls.sh status` (read-only).

## Foundation 0.6
Normal launch leaves the current notification service alone. Alerts reports external/disabled state, not fake history. To test real freedesktop notifications without taking Ryoku's bus name, stop the normal Oziro instance and run `bash native/notification-test.sh`. It creates a private D-Bus session, launches Oziro, waits for the notification owner and sends two test messages. Ctrl+C exits. Requires dbus-run-session, busctl and notify-send (libnotify); ordinary desktop applications still notify Ryoku. Some session-bus integrations may be unavailable inside the isolated test. This is not a replacement procedure for an existing notification daemon. Direct opt-in with OZIRO_NOTIFICATIONS=1 is for a standalone session only, after verifying no other daemon owns the name. No automatic takeover or service shutdown. Notification center has bounded session-only retention, plain-text rendering, clear/dismiss, count, timed latest-message toast and session-only DND. No action buttons, disk history, per-notification timeout fidelity or production lock-screen privacy integration yet. Do not use the experimental daemon for important notifications. All ten user-reported isolated notification tests passed on Niri; see TEST-006.md. This is not a production notification replacement.

## Foundation 0.7
Open Controls → Settings for the on-demand Theme Studio. The existing version-1 settings schema is extended with optional, validated accent, panel height, dock icon size and clock format fields. Existing favorites, energy preferences and dock toggle remain intact. Changes save automatically; slider sizes commit on release. Reset appearance resets only palette, custom accent, dimensions, placement and clock format. No external desktop files or compositor settings are edited. Preview is schematic; actual desktop changes are visible immediately for preset/accent/placement and after release for sizes. No wallpaper, arbitrary theme imports, full system theme integration or blur engine yet. All 14 reported checks passed on Niri; see TEST-007.md.

## Foundation 0.8
Controls → Energy opens the on-demand policy page. Adaptive (default) retains previous battery behavior; Balanced uses standard effects; Eco forces reduced effects. Manual Reduce effects overrides all modes, and Auto on battery applies only in Adaptive. Optional pause dock on battery in Eco unloads its surface while preserving pins and its saved enabled state. It returns when policy permits. Reactive UPower bindings; no new periodic jobs or automatic hardware changes. Service detection is read-only and only on opening/Refresh. A service's state is not proof that it controls power; system profile selection remains explicit in Control Center. `bash native/energy-status.sh` gives the same diagnostic. `bash native/power-sample.sh 300` estimates whole-system battery discharge on systems with one discharging battery exposing energy_now. Run unplugged with fixed brightness and workload, repeat baseline and Eco under matching conditions. Not an Oziro-only wattage estimate; short samples are noisy, hardware savings unverified. No CPU/GPU governor, charge threshold, or service modifications. See TEST-007.md. Runtime pending.
